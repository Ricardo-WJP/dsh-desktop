## 最终结论

0.1.46 已完成构建、覆盖安装、真实插件升级与正常模式重启验收。当前桌面端只存在一个顶层实例，DSH 固定运行在 `http://127.0.0.1:3080`，不会主动打开浏览器；16 个已安装插件均可被市场识别，在线检查没有待更新项。

本次验收不是只看文件是否存在。实际执行了插件候选复制、pnpm 安装、候选隔离启动、活动版本切换、回滚指针核对、正常重启、连续 HTTP 请求、进程树检查、安装版源码哈希比对、完整自动测试与生产依赖审计。

## 用小白能理解的话解释这次核心问题

以前插件升级像是在“正在住的房子里边拆边装”：Windows 的符号链接权限、候选目录缺文件、插件名称与清单不一致，任何一个环节出错都会把当前环境一起拖坏。

现在改成了“先复制一套样板房，再装修和验收”：

1. 桌面端复制当前可用环境到独立候选目录。
2. 插件只安装到候选目录，不碰正在使用的版本。
3. 检查插件真实名称、精确版本、完整性和依赖。
4. 单独启动候选 DSH，确认它真的能提供服务。
5. 全部通过后才切换活动指针；失败则删除候选并保留旧环境。

因此，市场插件自己更新后也不会覆盖这套修复。升级按钮调用的是桌面端拥有的事务桥，而不是 `dshmarket` 包内部那段易被替换的安装代码。

## 本次主要修复

### 1. Windows 插件复制与权限

- 不再依赖普通用户经常无权创建的目录符号链接。
- 候选复制使用有并发上限的独立文件复制；支持时使用 Windows 文件克隆加速，不支持时安全回退到普通复制。
- 没有使用硬链接，防止不可信插件脚本修改候选时连带污染活动版本。
- 外部链接、循环链接、越界路径和候选身份不一致都会直接拒绝。
- 新增测试证明候选里的文件被修改后，活动版本不会跟着改变。

真实 2 万余文件环境的复制基准从约 67.7 秒降到约 29.7 秒；运行中的电脑受杀毒和文件占用影响会更慢，但不再是假死。

### 2. 插件市场更新不会被市场自更新覆盖

- 市场安装、更新和激活都转交桌面端候选事务。
- 只接受当前 DSH 窗口与可信的精确插件来源。
- `dshmarket` 更新后，桌面桥仍属于客户端本体，不会随插件包被替换。
- 真实完成 `dsh-codex-connect` 与 `dsh-im` 两次市场升级，均通过候选验证后才切换。

### 3. 首次安装进度与推荐页

- 首次安装会显示复制候选、解析来源、安装插件、整理候选、运行验证和完成等阶段。
- 验收脚本等待上限由 3 分钟调整为 10 分钟，避免安全检查仍在运行时被误报为超时。
- 推荐页现在固定显示 6 个可选插件，第 6 个是 `dsh-reasoning-effort`。

### 4. 启动、单实例、浏览器与 3080 端口

- 桌面端保留单实例锁，不会再开出两个顶层应用。
- DSH 使用 `--port 3080 --no-open`，不会主动弹浏览器。
- 正常模式重启后完整启动约 8.1 秒；连续 3 次请求均返回 200，响应约 3–10 毫秒。

### 5. 窗口、主题与文件夹选择

- 启动页、推荐页与主界面读取同一套主题优先级；“跟随系统”不再沿用上一次手动主题。
- 浅色系统按钮使用深色图标，最小化和最大化有浅灰悬停，关闭保留 Windows 红色反馈。
- 标题拖动区、窗口缩放、圆角、Session Log 位置与边框回归测试均保留。
- Windows 文件夹选择器 worker 以正确的 Node 模式启动，路径解码和取消收尾链路均有测试覆盖。

## 代码审查后的优化建议

以下不是当前阻断问题，本次没有为了顺手重构再次改动稳定链路：

1. 打包仍是 `asar: false` 与 `compression: store`。优点是原生资源路径直观，缺点是文件很多、安装和首次复制较慢。未来可单独做 ASAR 迁移，但必须同时回归原生模块、补丁文件和插件运行时。
2. 市场页面目前能看到任务状态，但还不能逐项接收桌面端内部的细粒度百分比。建议后续增加只读进度通道，把“复制、安装、验证、激活”同步到市场任务卡。
3. 运行目录保留了多个已验证历史候选和快照，便于回滚，但会占磁盘。可增加“保留最近 2 个可用版本”的安全清理策略，绝不能直接清空整个运行目录。
4. Electron Builder 有重复依赖引用和未启用 ASAR 的构建提示，目前不影响运行；发布前适合单独整理构建配置。
