# 控制中心与稳定性基础改造

## 范围

用户选定控制中心 B「左右分栏工作台」。本次只重做桌面控制中心，不替换 DSH 工作区的按钮布局、插件动效、账号或模型配置。

继续完成的稳定性工作：异常退出后的进程身份保护、程序与用户数据分离、打包前验收。桌面程序版本和 DSH 运行时版本保持不同含义，不借用其他桌面项目的版本号。

## 数据与程序

- 新的独立数据根为受管运行时根目录下的 `user-data`，指针为 `data-home.json`。
- 首次采用原候选版本的数据时先复制、校验，再原子发布；保留原候选源。之后程序升级不再覆盖已发布的用户数据。
- DSH 原生 `DSH_HOME` 指向独立数据目录；`profiles` 内仅投影被验证候选的程序目录，数据目录本身不是链接。
- 迁移中断留下明确 journal；复制、校验、改名、指针发布之间的恢复必须验证内容和身份，不覆盖不明目录。
- 程序回退使用已记录的上一个候选，保留当前数据。数据快照恢复则先停止写入、创建救援备份，再恢复历史数据；失败时尝试恢复救援备份，无法证明安全时保留事务记录。
- 原有快照和数据源不自动删除，也不把旧数据目录快照混称为新的独立数据快照。

## 进程边界

根进程退出不能证明全部后代退出。Windows 上不对已失去身份的 PID 再执行树终止，防止 PID 重用伤及其他程序。普通一次性命令保留真实退出结果并明确后代未验证；长期服务丢失进程身份时保持不安全状态，不冒称清理完成。本次没有实现 Windows Job Object 容器。

## 验收层级

1. 单元与回归测试：状态机、数据目录、程序回退、救援恢复、进程退出和 IPC 权限。
2. `scripts/verify-managed-data-native.mjs`：启动真实 DSH，以完全隔离的合成数据执行 A→B→A 和快照/救援恢复。默认不读取真实用户的 active 或凭据。
3. 打包前 gate：本次构建输入的哈希绑定、独立 Electron 插件布局 fixture、原生数据 smoke。fixture 不冒充完整用户环境 E2E。
4. `test-support/control-center-preview.cjs`：真实编译后的 React 界面，合成 Host，深浅主题及 1400/760/520 宽度共 30 个视图；检查横向溢出并留图。
5. 实际安装版：最后限定 DSH 进程进行重新加载，再确认真实启动、独立数据、控制中心入口和已有工作区正常。
